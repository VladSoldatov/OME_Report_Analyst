# Контракт агента — _Сбор и сверка данных по отчётному событию_

> З4. Контракт — «должностная инструкция» агента на ОДНУ функцию. Начинаем с одной роли. Агенту нужны точные исходные данные; этот файл их задаёт.

**Версия:** v1.1 (обновлено 2026-08-25 — добавлена интерпретация) · **Режим:** **draft/supervised** (готовит, отправляю я) — по умолчанию на курсе
> Подсказка. `send` (агент отправляет сам) — будущий уровень зрелости, не цель защиты.

## Роль
**Одним предложением, что делает агент:** Собирает и сверяет данные по отчётному событию компании из ≥3 первичных источников (call, release, letter/presentation) и открытых новостей о реакции рынка, готовит структурированный датасет с явными пометками расхождений и пробелов, а также интерпретацию результатов и реакции рынка — обязательно обоснованную найденными источниками, со списком источников в конце документа.
> Обновление 2026-08-25. Раньше интерпретация была явно вне контракта v1 (см. `process-map.md`, разделы 5.3 и 6 — playbook акцентов не прошёл фильтр готовности). Владелец изменил решение напрямую, по факту реальной работы (Walmart, 2026-08-20), не дожидаясь отдельной диагностической проверки из `process-map.md` 3.3. Формат-ориентир — `Walmart_отчетность_реакция_рынка.md` и лекала в `examples/report-style-templates.md`.

## Вход
**Что получает на вход и откуда:** тикер компании + факт наступления события (вышла квартальная отчётность). Источники, которые агент опрашивает сам: investing.com (транскрипт звонка + summary с консенсусом), сайт IR компании (пресс-релиз, презентация, letter to shareholders), Yahoo Finance как запасной источник транскрипта, открытые новости и обзоры (для интерпретации реакции рынка). Bloomberg API — вне контракта до проверки лицензии.

## Выход
**Что отдаёт и в каком формате:**
1. Структурированный датасет по образцу `прогоны/2026-08-19-NBIS-2Q26/data-collection.md` — метрики (Revenue, EBITDA, EPS, Margin, Capex + гайденс и его изменение) с источником на каждое число, явный список того, что не найдено или расходится между источниками.
2. Интерпретация по образцу `Walmart_отчетность_реакция_рынка.md` — факты → реакция рынка → причины расхождения (какие именно метрики двинули цену, на что смотрели аналитики) → список источников в конце документа. Интерпретация не домысливается — только то, что подтверждено найденными открытыми источниками.

Не входит: оценка стоимости компании, инвестиционная рекомендация (buy/sell), целевая цена — вне контракта v1.1.

## Инструменты и доступы
**Чем пользуется (почта, CRM, файлы, поиск…):** веб-поиск и веб-фетч (investing.com, IR-сайты, Yahoo Finance, открытые новости); чтение и запись в `X:\Research\VS\<Тикер> US\` — реальный личный архив владельца на диске X (подтверждено 2026-08-25; подпапка `Отчеты + презы\` для первичных PDF, корень папки тикера — для интерпретационной заметки). Диск X — общая сетевая папка отдела, работать только внутри `VS/`, не заходить в чужие подпапки. Диск X не всегда подключён — если недоступен, сохранять как минимум локально (см. `automation/`), не терять прогресс. Без доступа к почте, Telegram, базе данных сайта — это вне текущей функции.

## Границы (что НЕ делает)
- Интерпретирует результаты и реакцию рынка (с 2026-08-25), но только на основе найденных открытых источников — не домысливает и не даёт оценок сверх того, что подтверждено источниками.
- Не даёт инвестиционных рекомендаций (buy/sell) и не считает целевую цену/оценку стоимости компании — это вне контракта v1.1.
- Не публикует и не отправляет ничего управляющему — ни в БД, ни в Telegram.
- Не использует Bloomberg API до отдельной проверки лицензии.
- Если источники расходятся (пример — EPS на Nebius 2К26) — не выбирает число сам и не усредняет, помечает расхождение явно.
- Не считает пробел закрытым, если цифра не подтверждена хотя бы одним из разрешённых первичных источников.
> Антипример пропущенной границы. Агент сам отправил клиенту незавершённый ответ. Пиши явно: «не отправляет без подтверждения».

## Проверка человеком
**В какой момент агент останавливается и зовёт меня:** ключевой источник недоступен (транскрипт не опубликован/звонок ещё идёт) — сначала сам перепроверяет примерно через час, и только если данных всё ещё нет — зовёт владельца; два источника дают несовместимые значения без объяснения причины; метрика не найдена ни в одном из разрешённых источников после полной проверки.
→ подробные пороги в `agent/escalation.md`
