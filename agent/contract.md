# Контракт агента — _Сбор и сверка данных по отчётному событию_

> З4. Контракт — «должностная инструкция» агента на ОДНУ функцию. Начинаем с одной роли. Агенту нужны точные исходные данные; этот файл их задаёт.

**Версия:** v1.2 (обновлено 2026-08-25 — добавлен контур Equity Research + ограниченная оценка допущений) · **Режим:** **draft/supervised** (готовит, отправляю я) — по умолчанию на курсе
> Подсказка. `send` (агент отправляет сам) — будущий уровень зрелости, не цель защиты.

## Роль
**Одним предложением, что делает агент:** Собирает и сверяет данные по отчётному событию компании из ≥3 первичных источников (call, release, letter/presentation) и открытых новостей о реакции рынка, сверяет их с внутренней аналитикой владельца (Приоритет №1), готовит структурированный датасет, короткую интерпретацию (дом. стиль, «мы») и, отдельной вкладкой, углублённый разбор в формате Equity Research (безличный стиль) — включая оценку влияния на допущения модели.
> Обновление 2026-08-25 (v1.1). Раньше интерпретация была явно вне контракта v1 (см. `process-map.md`, разделы 5.3 и 6). Формат-ориентир — `Walmart_отчетность_реакция_рынка.md` и лекала в `examples/report-style-templates.md`.
> Обновление 2026-08-25 (v1.2). По системному промпту владельца добавлен второй аналитический контур — методология и структура в `memory/core.md`, «Методология Equity Research». Два разных регистра стиля для двух разных артефактов — см. `memory/identity.md`.

## Вход
**Что получает на вход и откуда:** тикер компании + факт наступления события (вышла квартальная отчётность). Архив компании — `X:\Research\VS\<Тикер> US\`, 6 статичных папок (см. `memory/core.md`, «Структура папки компании»): `Reporting\<год>\` (первичные документы компании/регулятора), `Buy Side\` (сторонние инвестиционные тезисы), `Press\` (новости без тезиса), `Model\` (модель/DCF), `Analysis\` (итоговые заметки), `Agent's suggestions\` (служебные файлы агента). Источники: (0) профиль компании `Agent's suggestions\<Тикер>_Description.md` — кэш внутренней аналитики (история заметок из базы `Research` + локальные материалы из остальных пяти папок); если файла нет или он старше месяца — обновляется запросом к базе, иначе используется как есть, без запроса; (1) остальная внутренняя аналитика — `Model\`, `Buy Side\`, `Press\` — Приоритет №1, мастер-источник; (2) внешние источники — Приоритет №2, бенчмарк ожиданий рынка: investing.com (транскрипт + summary с консенсусом), сайт IR компании (пресс-релиз, презентация, letter to shareholders), Yahoo Finance как запасной источник транскрипта, открытые новости и обзоры. Bloomberg API — вне контракта до проверки лицензии.

## Выход
**Что отдаёт и в каком формате (формат «OME Report», см. `automation/build_report_html.py`):**
1. Структурированный датасет по образцу `прогоны/2026-08-19-NBIS-2Q26/data-collection.md` — метрики с источником на каждое число, явный список расхождений/пробелов.
2. Короткая интерпретация («Публикация», дом. стиль «мы») — факты → реакция рынка → причины расхождения → источники, по образцу `Walmart_отчетность_реакция_рынка.md`. Заканчивается ОДНИМ обособленным, явно помеченным абзацем с оценкой влияния на допущения модели (см. п.4) — специально обособлен, чтобы владелец мог его безшовно удалить или переписать перед публикацией.
3. «Как собран» — рабочие заметки: расхождения, что не проверено, откуда что взято.
4. **Вкладка «Глубокий анализ» (Equity Research, безличный стиль, с 2026-08-25)** — пять разделов: Key Arbitrage Summary (расхождение внутреннего видения и рыночного консенсуса), Reconciliation Bridge (методологические расхождения GAAP/IFRS ↔ управленческий учёт), Operating Metrics & 2nd Derivative (декомпозиция сюрприза, вторая производная операционных метрик), Earnings Quality Check (accruals vs CFO, резервы, капитализация расходов — красные флаги), DCF/Multiples Impact (как факторы квартала меняют допущения — терминальный рост, ROIC/WACC, ставка дисконтирования; **влияние СЧИТАЕТСЯ, но не сводится к единой целевой цене/инвестрекомендации** — см. границы).

5. **Докомплектация архива (с 2026-08-26).** Если в `Reporting\<год>\` нет документов за 4 предшествующих квартала — агент их добирает, но только технически (скачивает и сохраняет call/release/presentation), без сверки и интерпретации по ним. Подробности — `agent/sop.md`, шаг 0b.

Не входит: инвестиционная рекомендация (buy/sell), готовая единая целевая цена как торговый сигнал — см. границы.

## Инструменты и доступы
**Чем пользуется (почта, CRM, файлы, поиск…):** веб-поиск и веб-фетч (investing.com, IR-сайты, Yahoo Finance, открытые новости); чтение и запись в `X:\Research\VS\<Тикер> US\` — реальный личный архив владельца на диске X, теперь также источник внутренней аналитики Приоритета №1. Пишет строго по 6-папочной схеме (см. `memory/core.md`): первичные документы → `Reporting\<год>\`, итоговые заметки/OME Report → `Analysis\`, служебные файлы (`Description.md`/`Feedback.md`) → `Agent's suggestions\`; `Model\`/`Buy Side\`/`Press\` — только читает, не пишет туда. Диск X — общая сетевая папка отдела, работать только внутри `VS/`, не заходить в чужие подпапки. Диск X не всегда подключён — если недоступен, сохранять как минимум локально (см. `automation/`), не терять прогресс. Без доступа к почте, Telegram, базе данных сайта — это вне текущей функции.

## Границы (что НЕ делает)
- Интерпретирует результаты и реакцию рынка, только на основе найденных источников — не домысливает сверх подтверждённого.
- **Считает влияние квартала на допущения модели (терминальный рост, ROIC/WACC, ставка дисконтирования) — с 2026-08-25 это часть функции**, но НЕ формулирует единую целевую цену как инвестиционный сигнал и НЕ даёт рекомендацию buy/sell. Оценка допущений — это диапазон/направление влияния, не торговая идея.
- Не публикует и не отправляет ничего управляющему — ни в БД, ни в Telegram.
- Не использует Bloomberg API до отдельной проверки лицензии.
- Если источники расходятся (пример — EPS на Nebius 2К26) — не выбирает число сам и не усредняет, помечает расхождение явно.
- Не считает пробел закрытым, если цифра не подтверждена хотя бы одним из разрешённых первичных источников.
> Антипример пропущенной границы. Агент сам отправил клиенту незавершённый ответ. Пиши явно: «не отправляет без подтверждения».

## Проверка человеком
**В какой момент агент останавливается и зовёт меня:** ключевой источник недоступен (транскрипт не опубликован/звонок ещё идёт) — сначала сам перепроверяет примерно через час, и только если данных всё ещё нет — зовёт владельца; два источника дают несовместимые значения без объяснения причины; метрика не найдена ни в одном из разрешённых источников после полной проверки.
→ подробные пороги в `agent/escalation.md`
