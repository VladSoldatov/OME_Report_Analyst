# SOP — процедура функции _Сбор и сверка данных по отчётному событию_

> З5. Пошаговая процедура: как именно функция выполняется. Простая нотация, без BPMN. Если не можешь описать шаги, значит, ещё не понимаешь процесс и автоматизировать рано.

> Процедура ниже собрана не абстрактно, а по факту двух реальных прогонов — Nebius (2026-08-19) и CoreWeave (2026-08-20). Шаги — то, что мы действительно делали оба раза.

## Нотация: вход → действия → выход → правила → исполнитель

**Вход:** тикер компании + факт наступления события (вышла квартальная отчётность) → от владельца (пока вручную; автоматическое отслеживание календаря — Занятие 6/8).

**Действия (по шагам):**
0. **Обязательный первый шаг: профиль компании `Agent's suggestions\<Тикер>_Description.md`.** Архив компании — 6 статичных папок, см. `memory/core.md`, «Структура папки компании»: `Reporting\<год>\`, `Buy Side\`, `Press\`, `Model\`, `Analysis\`, `Agent's suggestions\`.
   - Файла нет в `X:\Research\VS\<Тикер> US\Agent's suggestions\` → запрос к базе `Research` (dsp-w-mssql-1, Windows auth) за историей заметок по компании (кто из аналитиков писал, когда, тезис) + чтение уже имеющихся локальных файлов (`Model\`, `Buy Side\`, `Press\`) → собрать файл впервые.
   - Файл есть, дата «Обновлено» ≤ 1 месяц назад → использовать как есть, к базе НЕ обращаться.
   - Файл есть, дата «Обновлено» > 1 месяца назад → повторный запрос к базе, обновить файл.
   Это Приоритет №1, мастер-источник для интерпретации. Только после этого шага — во внешние источники (шаги 1+), они бенчмарк ожиданий рынка, не отправная точка. Подробности формата — `memory/core.md`, «Профиль компании».
   **Заодно (тот же шаг 0) — проверить `Agent's suggestions\<Тикер>_Feedback.md`.** Необязательный, перезаписываемый файл — владелец кладёт туда финальный текст своей реально опубликованной заметки (если разошёлся с черновиком агента) или короткий комментарий, когда есть желание. Если дата внутри файла новее последней уже разобранной обратной связи — разобрать: смысловая правка → строка в журнал «ошибка → правка» в `memory/core.md`; стилевая правка → `examples/report-style-templates.md`. Файл не очищать самому. Подробности — `memory/core.md`, «Обратная связь по черновикам агента».
0b. **С 2026-08-26 — проверка глубины архива `Reporting\<год>\`: если отсутствуют данные за 4 предшествующих квартала, их нужно ДОБРАТЬ.** Набор типов документов не универсален — не предполагать шаблон «call+release+presentation» для любой компании: сверяться с тем, что компания реально публикует (её investor-hub/IR-страница), и добирать именно это. Пример: у Nebius нет отдельной slide-презентации — только call, release и Letter to shareholders (см. `memory/core.md`, журнал 2026-08-26, где ранее сохранённый файл был по ошибке назван «presentation», хотя титульный лист документа прямо говорит «Letter to shareholders»). Только техническая часть — скачать и сохранить сами документы тем же методом, что и для текущего квартала (шаги 1–3a, 7, 7a), без сверки цифр, без датасета, без интерпретации по ним; это докомплектация архива, не 4 новых прогона. Если компания публична меньше 4 кварталов (пример — SpaceX, IPO июнь 2026) — добирать только реально существовавшие кварталы, не выдумывать более раннюю историю. Если исторический документ не находится после одной попытки — не останавливать весь прогон: пометить пробел (документ просто не сохранён в `Reporting\<год>\`) и продолжать текущий прогон. Обычные правила эскалации (`agent/escalation.md`) относятся к ТЕКУЩЕМУ кварталу, не к этой фоновой докачке истории.
1. Искать официальный источник компании с полными GAAP-таблицами первым — «Earnings Presentation» / «Financial results» на сайте/CDN компании (сработало чисто на CoreWeave — EPS без расхождений).
2. Если такого документа нет или он неполный (как у Nebius — letter не содержит EPS) — искать call transcript. **Порядок с 2026-08-26, уточнён 2026-08-26 (приоритет — текст, не видео, из-за стоимости в токенах):**
   1. **Текстовые источники — приоритет по умолчанию.** Investing.com — сначала общий веб-поиск, если не находится, проверить напрямую страницу компании на investing.com (`/equities/<slug>-earnings`): общий поиск может не проиндексировать более старую статью-транскрипт, даже если она существует. Запасной текстовый источник — Yahoo Finance.
   2. **Сразу после получения любого транскрипта — проверка на полноту, прежде чем считать источник закрытым:** длина текста заметно (в разы) меньше, чем у транскриптов той же компании за другие кварталы, ИЛИ в тексте есть маркеры пейволла («Premium», «Upgrade to unlock», «Sign in to continue» и т.п.) → это ПАРЦИАЛЬНЫЙ источник. В этом случае — попробовать оставшийся текстовый вариант из п.1, прежде чем сдаваться.
   3. **Официальный webcast компании (например, ссылка «Webcast» на её `financials`/IR-странице) — ПОСЛЕДНИЙ резерв, не приоритет,** несмотря на то, что это первичный источник: чтение готовой текстовой статьи на порядок дешевле по токенам, чем просмотр/транскрибация видео. Если ни один текстовый источник не дал полного транскрипта — зафиксировать ссылку на webcast как потенциальный источник (в датасете/профиле компании) и оставить это пробелом как обычно, НЕ обрабатывать видео самостоятельно. Переходить к фактической транскрибации видео только по прямому запросу владельца — это осознанное, недешёвое действие, не действие по умолчанию.
   Отдельно искать пресс-релиз.
3. Если источник уже готовый PDF (например, официальный релиз с CDN компании) — скачать (fetch) и прочитать напрямую как файл, не пытаться распарсить как HTML-текст.
3a. **Если источник — HTML-страница (транскрипт на investing.com, пресс-релиз на wire-сервисе типа PRNewswire, любая страница без готового PDF) — основной метод: `python automation/fetch_page.py <url> <output_prefix>`.** Скрипт открывает страницу в настоящем headless-браузере (Playwright/Chromium, уже установлен) и сохраняет и `.pdf` (реальный снимок страницы для архива), и `.txt` (текст после полной отрисовки JS — надёжнее, чем WebFetch, который только пересказывает контент, и чем прямой `curl`, который может упереться в Cloudflare-проверку). Проверено на транскрипте investing.com (LEU, 2026-08-25) — прошёл Cloudflare-проверку с первой попытки, тогда как `curl` иногда блокируется.
4. Извлечь обязательные метрики (Revenue, EBITDA, EPS, Margin, Capex + гайденс и его изменение), для каждой цифры — источник (документ и страница/раздел).
5. Сверить цифры между источниками. При расхождении — не выбирать и не усреднять, фиксировать как открытый вопрос владельцу.
6. **Обязательный порядок, не пропускать даже если пересказ WebFetch выглядит достаточным:** сначала СОХРАНИТЬ найденный первичный документ в `X:\Research\VS\<Тикер> US\Reporting\<год>\` (реальный личный архив на диске X; если диск недоступен — временно локально, см. `automation/`) с понятным именем (call/release/letter/presentation + квартал), и только ПОТОМ извлекать из уже сохранённого файла цифры и цитаты для датасета и интерпретации. Пересказ WebFetch — черновой ориентир, не источник для итогового текста; если сохранить не удалось (после разумной попытки) — прямо писать в датасете «первоисточник не сохранён, ниже — по пересказу», не выдавать пересказ за проверенные данные молча.
7. Если попытка получить документ напрямую (curl или fetch) вернула технический блок (Cloudflare-проверка, таймаут) — это не то же самое, что paywall с реальным отказом в контенте. Один раз повторить запрос той же ссылки чуть позже, прежде чем считать источник недоступным. Если `fetch_page.py` (Playwright) не может подключиться к странице вообще (не таймаут на рендере, а обрыв на самой ранней стадии навигации) — это может быть анти-бот детект именно headless-браузера; после 2–3 попыток с разными стратегиями ожидания не упорствовать, переключиться на обычный `curl`.
7a. **Если источник получен через `curl` (не через `fetch_page.py`) — прогонять HTML через `python automation/html_to_text.py <input.html> <output.txt>`, не писать разбор HTML вручную заново.** Самодельный regex-разбор HTML на лету — источник ошибки: теги можно случайно заменить на пробелы вместо переносов строк, и весь документ склеится в один нечитаемый абзац (было на пресс-релизе X-Energy, 2026-08-25) — так же можно пропустить целые таблицы/разделы, которые в потоке текста визуально не отличить от остального. Готовый скрипт сохраняет переносы строк на границах абзацев/таблиц.
8. Собрать датасет (метрики + провенанс + явные пробелы) и сохранить в `прогоны/<дата>-<Тикер>-<квартал>/data-collection.md`.
9. Составить чистую человекочитаемую сводку — с 2026-08-25 включает интерпретацию (факты → реакция рынка → причины расхождения, какие метрики двинули цену) на основе открытых новостей и обзоров, с явным списком источников в конце — сохранить в `X:\Research\VS\<Тикер> US\Analysis\` (если диск недоступен — временно локально). Формат-ориентир: `Walmart_отчетность_реакция_рынка.md`, лекала стиля — `examples/report-style-templates.md`.
9a. **С 2026-08-25 — дополнительно собрать «OME Report»**: единый HTML-файл с вкладками (Комментарий / Пресс-релиз / Транскрипт, опционально Презентация) для удобного локального чтения — `python automation/build_report_html.py`. Имя файла — `<Тикер> <квартал> - отчёт.html`, сохраняется в `X:\Research\VS\<Тикер> US\Analysis\` рядом с `.md`-заметкой. Не публикуется никуда — только для локального просмотра в браузере.
9b. **С 2026-08-25 — вкладка «Глубокий анализ» (Equity Research).** Пять разделов по методологии из `memory/core.md` («Методология Equity Research»): Key Arbitrage Summary, Reconciliation Bridge, Operating Metrics & 2nd Derivative, Earnings Quality Check, DCF/Multiples Impact. Пишется безличным стилем (без «мы»), в отличие от короткой «Публикации». Оценка влияния на допущения модели считается здесь подробно; в короткой «Публикации» из неё выносится только один обособленный абзац (см. `agent/contract.md` v1.2).
10. Если ключевой источник недоступен — самостоятельно повторить попытку примерно через час; если данных всё ещё нет — остановиться и спросить владельца.

**Выход:** структурированный датасет + отдельная чистая сводка по кварталу, с провенансом на каждую цифру и явным списком пробелов/расхождений.

**Правила (что соблюдать на каждом шаге):** приоритет источников для ЦИФР — официальный PDF > shareholder letter > call transcript > агрегаторы; для ИНТЕРПРЕТАЦИИ — внутренняя аналитика владельца (Приоритет №1, шаг 0) поверх внешнего консенсуса (Приоритет №2); расхождение никогда не сглаживается; пробел не восстанавливается по догадке; исходники и черновики агента хранятся раздельно и только в архиве владельца (`X:\Research\VS\<Тикер> US\`), не в служебных папках инструмента; интерпретация не считается завершённой без списка источников в конце документа.

## Что упростили/удалили перед автоматизацией
- Не идём за Cash/структурой долга отдельным глубоким поиском, если это не лежит в том же документе, что остальные метрики (подтверждено на CoreWeave) — фиксируем как пробел, не тратим время на SEC-обход (SEC всё равно блокирует автозапросы).
- Не сравниваем с внешним консенсусом аналитиков отдельно — консенсус у разных агрегаторов расходится сильнее, чем сам факт; фокус на факт vs гайденс компании, это и есть источник главного сигнала.
- Bloomberg API сознательно исключён до проверки лицензии.
> Подсказка. Сначала исправляем процесс, затем передаём его агенту. Плохо устроенный процесс после автоматизации лишь быстрее создаёт ошибки.

## Чек-лист готовности данных
- [x] **Доступность** — да: оба раза агент сам дотянулся до нужных документов без участия владельца, кроме тикера на входе.
- [x] **Структура** — да, с одной технической оговоркой: PDF нужно сначала скачать, потом читать напрямую (уже в `core.md`).
- [ ] **Полнота** — частично: EPS не всегда в основном документе (Nebius), Cash не всегда рядом с остальными метриками (CoreWeave). Не блокирует функцию — пробел называется явно, это и есть проверяемый результат, а не «100% данных всегда».
- [x] **Качество** — да, для первичных источников; вторичные агрегаторы качество не гарантируют (расхождения по EPS дважды), поэтому исключены из основного пути.

> Предупреждение. Если хотя бы по одному пункту ответ «нет», сначала наводим порядок, а в `memory/core.md` фиксируем источники и правила.
