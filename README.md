# OME Builder Intensive — рабочий репозиторий студента

Это готовая рабочая папка курса. Ничего переносить из `templates/` не нужно: все файлы уже лежат по тем путям, которые используют Claude Code и проверяющий агент.

Начни с [`START_HERE.md`](START_HERE.md). До первого занятия установка и проверка занимают около 15 минут, если Git, Node.js и Claude Code уже установлены.

## Что будет готово после занятия 1

- проверенный рабочий репозиторий;
- заполненный `memory/identity.md` — профиль агента, владелец и границы;
- первая версия `memory/core.md` — факты, правила, источники и пример результата;
- раздел 1 `blueprint.md` — гипотеза OME и форма продукта.

## Как работать

1. Запускай Claude Code из корня этой папки. Корневой `CLAUDE.md` подключает `memory/identity.md` и `memory/core.md`.
2. Заполняй только файлы текущего занятия. Порядок разделов отмечен метками `З_` в шаблонах.
3. Сохраняй изменения в Git после каждой законченной части.
4. Не добавляй пароли, API-ключи, персональные данные клиентов и сведения, которые нельзя передавать поставщику модели.
5. После З1 запускай локальную проверку по инструкции, которую даёт ведущий. Она даёт локальный результат; официальный статус подтверждает ведущий.

## Что не редактировать

- `CLAUDE.md`, если ведущий не попросил изменить его;
- `examples/` — это примеры для сверки.

## Важное ограничение проверяющего агента

Закреплённая версия `ome-grader` поддерживает только З1. Она работает локально на компьютере студента и не требует серверной модели или ключа курса, но обращение к модели через Claude Code использует учётную запись студента. Локальный результат можно подделать, поэтому он не равен официальному зачёту.

## Условные обозначения в шаблонах

| Знак | Значение |
|---|---|
| `_…_` | впиши сюда |
| `> Подсказка.` | как заполнять поле |
| `> Пример.` | пример хорошего ответа |
| `> Антипример.` | частая ошибка |
| `З_` | на каком занятии заполняется раздел |
| `Граница.` | точка, где агент останавливается и обращается к человеку |
| `Готово, если` | критерии приёмки файла в конце шаблона; их же смотрит проверяющий агент |

## Как устроен каждый рабочий файл

Все файлы построены одинаково — как страницы одной рабочей тетради. Привыкнешь к одному, поймёшь все:

1. **Заголовок** — что это за файл.
2. **Блок `>` сверху** — зачем файл и текстовая метка `З_`, когда заполняешь.
3. **Поля `_…_`** с подписями рядом: `> Подсказка.` объясняет, как заполнять; `> Пример.` показывает ответ; `> Антипример.` называет ошибку.
4. **`Готово, если`** в конце — критерии приёмки, которые смотрит проверяющий агент.

Заполняешь сверху вниз по меткам занятий. Не знаешь, с чего начать день занятия, — открой шаблон с ближайшей меткой `З_`.

## Сквозная дисциплина

- **Порядок:** удалить → упростить → делегировать → автоматизировать. Не автоматизируй то, чего быть не должно.
- **Не автоматизируй хаос:** нельзя отдать агенту процесс, который сам не понимаешь.
- **Разовая помощь ИИ и системная работа — разные вещи:** функция должна быть описана, выполняться по правилам и проходить проверку человеком.
- **5 критериев OME** — линейка на каждом решении, критерии разбирает праймер OME от ведущего.

## Условия

Курс идёт на реальном бизнесе и реальных данных. Итоговая защита — одна функция, работающая под надзором: агент готовит результат, владелец проверяет и отвечает за него.
