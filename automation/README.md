# Синхронизация с диском X

Диск X (`X:\Research\VS\<Тикер> US\...`) — реальный рабочий сетевой архив владельца по компаниям (см. `memory/core.md`), не всегда подключён (VPN/сеть/не тот компьютер). Черновики и датасеты агента должны сохраняться минимум локально всегда и синхронизироваться на X, когда диск доступен — без риска потерять прогресс и без риска перезаписать или удалить что-то на общей сетевой папке (диск X общий с коллегами).

## Как это работает

1. В течение сессии Claude Code результаты сохраняются локально в `C:\Users\vladislav.soldatov\OME_Coverage_Staging\<Тикер> US\...` — той же структурой, что и на диске X: 6 статичных папок (см. `memory/core.md`, «Структура папки компании») — `Reporting\<год>\` для первичных PDF, `Analysis\` для итоговой заметки/OME Report, `Agent's suggestions\` для служебных файлов агента.
2. Скрипт `sync-to-diskX.ps1` по расписанию (Планировщик задач Windows, каждые 30 минут) проверяет, доступен ли `X:\Research\VS`.
3. Если доступен — копирует новые/изменённые файлы из стейджинга на X (`robocopy /E /XO`, без `/MIR`) — **никогда не удаляет и не перезаписывает более новые файлы на X**. Если недоступен — пропускает и логирует это.
4. Лог всех прогонов — `C:\Users\vladislav.soldatov\OME_Coverage_Staging\_sync-log.txt`.

## Установка (один раз, без прав администратора)

```powershell
schtasks /create /tn "OME Sync to Disk X" /tr "powershell.exe -NoProfile -WindowStyle Hidden -ExecutionPolicy Bypass -File \"C:\Users\vladislav.soldatov\OME_Report_Analyst-1\automation\sync-to-diskX.ps1\"" /sc minute /mo 30 /rl limited /f
```

Задача создаётся от текущего пользователя, запускается каждые 30 минут, пока пользователь залогинен (доступ к сетевому диску X всё равно требует активной сессии — фоновый запуск «не залогинен» не даст результата другим способом).

Проверить: `schtasks /query /tn "OME Sync to Disk X"`
Запустить вручную (для теста): `schtasks /run /tn "OME Sync to Disk X"`
Удалить: `schtasks /delete /tn "OME Sync to Disk X" /f`

## Почему так, а не иначе

- **Планировщик задач, а не фоновый Python-процесс** — не требует держать процесс живым, переживает перезагрузки, не плодит зависшие процессы.
- **Только копирование, никогда `/MIR` и никогда удаление** — диск X общий с коллегами (`ABulgakov`, `AGromadin`, `RomanK` и др. — соседние папки на том же диске); ошибка в пути не должна стирать чужую работу. Скрипт синхронизирует только `VS/` — папку владельца.
- **Направление одностороннее** (стейджинг → X) — никогда не тянет изменения обратно с X, чтобы не перезаписать то, что владелец правит вручную прямо на диске.
